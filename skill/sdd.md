# Spec-Driven Development

## Workflow
1. Understand the requested change.
2. Inspect current architecture and code.
3. Write/update a specification.
4. Define acceptance criteria.
5. Identify data/model/UI contracts affected.
6. Implement the smallest change.
7. Run tests and validation.
8. Update documentation.
9. Confirm the implementation satisfies the specification.

## Specification structure
- Context
- Problem
- Goal
- Non-goals
- Requirements
- Data contract
- Technical design
- Acceptance criteria
- Risks
- Validation plan

## Rules
- Do not code before the specification is sufficiently clear.
- Do not silently expand scope.
- Flag ambiguous requirements.
- Update the specification when implementation decisions materially change.
- Keep academic assumptions explicit.
